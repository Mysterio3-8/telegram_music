## ✅ ЗАКРЫТО 2026-08-01 (не переделывать)

### Приоритет 1 — «бот отвечает 20 секунд»

Причина оказалась не в коде бота и не в базе. Подробный разбор — в
[CLAUDE.md](CLAUDE.md), раздел «ИНЦИДЕНТ (2026-08-01)». Коротко:

| | Было | Стало |
|---|---|---|
| load average (1 ядро) | **15.24** | **0.05** |
| Доступно RAM | 30 МБ | ~200 МБ |
| Swap | 2047/2047 (полностью) | 815/2047 |
| Redis в памяти | 724.9 МБ | **1.69 МБ** |
| RDB-снимок на диске | 125 МБ | **42 КБ** |

- **`tg-music-worker` рестартовал каждые 6–12 секунд круглосуточно**
  (`NRestarts=10261`): prefork-пул с `concurrency=2` = три интерпретатора внутри
  `MemoryMax=200M`, влезть не мог физически. Переведён на `--pool=threads`.
- **Предохранитель `StartLimitBurst=5` на всех воркерах** — systemd больше не
  устраивает бесконечный шторм рестартов, а сдаётся и оставляет юнит в failed.
- **Очередь `youtube` в Redis на 644 293 задачи (651 МБ) удалена** с согласия
  владельца — осиротевшие задачи выключенного массового парсера.
- Уникальные `-n <очередь>@%h` — `DuplicateNodenameWarning` больше нет.
- `--without-gossip --without-mingle --without-heartbeat` на всех воркерах.
- Очередь `telegram_channel` влита в основной воркер, отдельный юнит удалён.
- `tg-music-soundcloud` остановлен: юнит `disabled` (решение владельца 27.07),
  очередь пуста, а процесс занимал 180 МБ из 961 МБ.
- **Мидлварь замера** [app/middlewares/timing.py](app/middlewares/timing.py):
  логирует обработку дольше 1 сек с именем хендлера. Смотреть:
  `journalctl -u tg-music-bot | grep МЕДЛЕННО`.
- **База не при чём:** полный скан 30 150 треков — 0.2 сек. `ix_tracks_search_index`
  существует, но `LIKE '%…%'` его не использует и на этом объёме не должен.
  FTS5 понадобится сильно позже.
- `tg-music-youtube-scan.service` в failed — стухший след от последнего запуска
  перед выключением массового парсера (таймер `disabled` с 27.07). Снят
  `reset-failed`, чинить нечего.

### Грабли деплоя (важно)

`git pull` обновляет `deploy/*.service`, но systemd читает `/etc/systemd/system` —
правка юнита сама туда не попадает. Появился
[deploy/install-units.sh](deploy/install-units.sh), идемпотентный, запускать
**на сервере от root**: `cd /opt/tg-music-bot && bash deploy/install-units.sh`.
Он не поднимает `disabled`-юниты, чтобы не отменять втихую решения владельца.

## 🔴 ЧТО ОСТАЛОСЬ — ДЕЙСТВИЯ ВЛАДЕЛЬЦА

Эти три пункта не может закрыть никто, кроме владельца.

1. **Отключить парольный вход по SSH.** fail2ban уже стоит, но это половина
   защиты. Вход по ключу у root настроен и работает (единственный пользователь
   с шеллом — root, ключ один). Выполнить на сервере:
   ```bash
   printf 'PasswordAuthentication no\nKbdInteractiveAuthentication no\n' > /etc/ssh/sshd_config.d/01-hardening.conf && sshd -t && systemctl reload ssh && sshd -T | grep -i passwordauth
   ```
   Имя файла важно: дропины читаются по алфавиту и побеждает первое значение,
   а `50-cloud-init.conf` уже содержит `PasswordAuthentication yes`.
   Проверить новым подключением **не закрывая текущее**. Откат — удалить файл
   и `systemctl reload ssh`.
2. **Живой платёж 29 ₽ картой** — деньги тестом не покрыты. Заодно проверить
   автопродление (рекуррент).
3. **Скрины для поста** — список из 6 кадров лежит комментарием в
   [NEWS.md](NEWS.md) под постом «Пост +1». Затем опубликовать: «Пост +2 —
   Честно про 29 ₽» (личный, первым) и «Пост +1» (со скринами).

## ⚠️ ГРАБЛИ (не наступать снова)

- **`MemoryMax` без проверки, влезает ли в него пул воркера**, превращается из
  защиты в генератор нагрузки (инцидент 2026-08-01). Меняешь `concurrency` или
  пул — пересчитай потолок. Для celery на этом боксе только `--pool=threads`.
- **`ps`/`top` врут про Redis, когда память выдавлена в своп**: RSS 5.88 МБ при
  реальных 724 МБ. При любой жалобе на память — `redis-cli info memory`,
  `redis-cli llen <очередь>`, `redis-cli memory usage <ключ>`.
- **Юниты не доезжают через `git pull`** — нужен `deploy/install-units.sh`.
- **SQLite и кириллица**: `lower()`/`ILIKE` понижают только ASCII. Поиск по
  русским буквам — только через `search_index`. При проверке сырым SQL помнить,
  что приложение дополнительно транслитерирует запрос: «кизару» в базе даёт 0,
  а «kizaru» — 240, и это правильно, а не баг.
- **MusicBrainz**: 1 запрос/сек на IP, два прогона параллельно нельзя.
- **Долгие прогоны на VPS**: только `setsid nohup … &`, ждать по PID (`kill -0`),
  **не** по `pgrep` имени — pgrep находит сам вотчер и цикл не кончается.
- **Этот бокс не тянет агрессивный парсинг**: `discover_loop` и
  `recover_covers --limit 30000` **не запускать**.
- **Redis при флуде**: счётчики антиспама держим в памяти намеренно.
