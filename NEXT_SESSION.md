## 🔴 ПРИОРИТЕТ №0 — «Deceptive Website Warning» на iOS

**Симптом:** при открытии Mini App в Telegram на iPhone вместо плеера — красный
экран Safari «Deceptive Website Warning». Владелец подтвердил 21.07: **у всех, не
только у него**. iOS-аудитория отрезана от Mini App, это блокер выручки.

### Что сделано 04.08 — устранён профиль фишингового сайта

Прошлые сессии искали причину в контенте Mini App и в базе Google, обе проверки
были чистые, и на этом расследование останавливалось. Проверили не то место:
**на фишинг-кит был похож не контент, а поведение веб-сервера.**

В nginx стоял SPA-фолбэк `try_files $uri /index.html`. Он отдавал **200 OK и
HTML на ЛЮБОЙ путь**. Замерено на живом проде до правки:

| Запрос | Было | Стало |
|---|---|---|
| `/apple-id/verify` | 200 text/html | 404 |
| `/paypal`, `/bank/secure`, `/signin` | 200 text/html | 404 |
| `/wp-login.php`, `/phpinfo.php` | 200 text/html | 404 |
| `/.env`, `/.git/config`, `/.git-credentials` | 200 text/html | 404 |
| `/actuator/heapdump`, `/terraform.tfstate` | 200 text/html | 404 |
| `/9WOLF.php`, `/1.php` и ещё ~1500 путей вебшеллов | 200 text/html | 404 |

В ротации логов nginx — **2014 уникальных путей, отдавших 200**, почти все это
сканеры вебшеллов и утечек секретов. Месяцами любой сканер интернета видел
домен, у которого «есть» и страница проверки Apple ID, и открытый `/.env`, и
десяток вебшеллов. Отдельно показателен путь `/crusader-404-probe` — сканер
специально проверяет, умеет ли хост отдавать 404, и получал 200.

Наложите на это остальной профиль: домен зарегистрирован **27.04.2026** (три
месяца, проверено по whois — значит версия «остаточная репутация от прошлого
владельца» **закрыта**, владелец первый), дешёвая зона `.cc`, и страница, которая
без JS отдаёт **пустой `<div id="app">`** при заголовке «TG Music» и скрипте с
`telegram.org`. Для классификатора это новый домен в рисковой зоне, мимикрирующий
под бренд Telegram, показывающий краулеру пустоту, а людям — что-то другое
(признак клоакинга), и раздающий 200 на пути вебшеллов.

**Правки (коммит `e7b0ed7`, задеплоено):**
- `location /` → `try_files $uri $uri/ =404`. Клиентского роутера у Mini App нет
  (все экраны — состояние в памяти, `pushState` не используется — проверено
  грепом), поэтому фолбэк был не нужен вообще: «/» отдаёт index-директива
- в `#app` лежит настоящее содержимое: что за сервис, ссылки на бота и
  поддержку, дисклеймер о непринадлежности к Telegram. Первый `render()`
  перезаписывает его, пользователь этого не видит; видят краулеры и тот, у кого
  не догрузился JS (раньше он видел белый экран)
- `robots.txt`, `/.well-known/security.txt`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy`, `.md` наружу не отдаётся
- meta description + Open Graph

**Регрессия проверена на реальном трафике:** все 2014 исторических путей с 200
прогнаны через новый конфиг. Сломанных живых путей ноль — 404 получили только
сканерные пробы. Живые пути проверены отдельно: `/`, `/index.html`, `/src/**`
(весь граф импортов), `/assets/**`, `/api/*`, `/webhook/*` — 200.

### Чего это НЕ доказывает

Прямой причинно-следственной связи с предупреждением Safari нет — её нельзя
установить, не имея доступа к тому, как классифицируют Apple и Google. Сделано
то, что доказуемо выглядело плохо и было в нашей зоне контроля. Если
предупреждение переживёт эти правки — переезжаем на новый домен, и вот тогда
чистый домен уже не унаследует эту проблему (а до правки унаследовал бы за
пару недель — сканеры находят новый домен быстро).

Что ещё проверено 04.08 и **чисто**: Spamhaus DBL, SURBL, URIBL по домену;
Spamhaus ZEN и SpamCop по IP `38.244.213.132`; сертификат Let's Encrypt валиден
до 10.10.2026; на сервере нет посторонних vhost'ов, default-сайт — заглушка
Debian.

### Шаг 2 (за владельцем) — апелляция в Safe Browsing

Форма в обход Search Console:
`https://safebrowsing.google.com/safebrowsing/report_error/?url=https://keybest.cc`

Текст:

> keybest.cc is the web interface of TG Music, a legitimate music player that
> runs as a Telegram Mini App. The site is owned and operated by me; domain
> ownership is verified in Google Search Console via DNS TXT record.
>
> Search Console reports "No issues detected" and the Safe Browsing Transparency
> Report shows no unsafe content, yet iOS Safari still displays a "Deceptive
> Website Warning" for all visitors.
>
> The site loads exactly one third-party script — the official Telegram Mini App
> SDK from telegram.org. There are no redirects to other domains, no credential
> forms and no data collection outside the Telegram authentication flow.
>
> A misconfiguration on my side has been fixed: the web server used an SPA
> fallback that returned HTTP 200 for every path, including paths commonly
> probed by scanners. Unknown paths now correctly return 404.
>
> Please re-review the site.

Ответ занимает несколько дней.

### Шаг 3 — переезд на новый домен

Если после шагов 1–2 за 3–5 дней ничего не изменилось. Владельцу купить домен в
зоне **`.ru` (~200–300 ₽/год)**, `.com` или `.app`. Не `.cc`, не `.tk/.gq/.ml`.

Дальше — одна команда на сервере от root:

```bash
cd /opt/tg-music-bot && bash deploy/migrate-domain.sh новый-домен.ru
```

Скрипт ([deploy/migrate-domain.sh](deploy/migrate-domain.sh)) проверит A-запись,
соберёт nginx-сайт из шаблона, выпустит сертификат, поправит `PUBLIC_BASE_URL` и
`API_CORS_ORIGINS` в `.env` (с бэкапом), повесит на `keybest.cc` 301 на новый
домен, перезапустит сервисы и прогонит проверки. Идемпотентен.

Два шага он сделать не может, их владелец делает руками (скрипт напомнит в
конце): **@BotFather → Menu Button → новый URL** и **вебхук в ЛК ЮKassa →
`https://новый-домен/webhook/yookassa`**. Плюс потом обновить домен в CLAUDE.md,
этом файле и `miniapp/README.md`.

## 🟡 Мониторинг памяти и диска — единственная незакрытая инфраструктурная дыра

Про проблемы с ресурсами узнаём, только когда владелец пишет «бот тормозит».
Так было трижды: 26.07 (диск 100%), 01.08 (воркер в OOM-петле), 03.08 (массовый
парсер подняли руками, память 883 из 961 МБ). Каждый раз симптом доходил до
пользователей раньше, чем до нас.

Нужен лёгкий скрипт раз в 5–10 минут: `free`/`df` → при <150 МБ RAM или <500 МБ
диска шлёт владельцу алерт в Telegram. Ещё полезно сторожить размер очередей
Redis (`redis-cli llen`) — дважды именно они съедали память, и `ps` про это
врёт, потому что Redis уходит в своп.

## Заморожено — не начинать, не предлагать

Выключено осознанно, инфраструктура цела:

- **Массовый парсер 24/7** (`tg-music-soundcloud`, `tg-music-youtube`,
  `tg-music-youtube-scan.timer`). Защищён флагом
  `ConditionPathExists=/etc/tg-music-mass-parser-on` — без файла не стартует
  даже от `systemctl start`. Включать только на большом сервере
- **Автодискавери артистов** (`discover_loop.sh`) — убит, юнита нет
- **Восстановление обложек** (`app.cli.recover_covers`) — прогон убит 26.07,
  код готов; не запускать до нового сервера
- **PostgreSQL** (срез 2 SPEC-2.0) — прод на SQLite (WAL, busy_timeout)

Отменено решением владельца: караоке, магазин битов, веб-админка, реклама
внутри аудиопотока, Premium для артистов, помесячное чередование подписки.

Не проверено из SPEC-2.0, срез 7: тариф «навсегда» (10000 ₽) по плану должен был
уйти из прямой продажи и остаться наградой за рефералку — сейчас всё ещё
продаётся напрямую.

## Тесты и деплой

420 тестов, все зелёные на 04.08. Перед коммитом:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Деплой — скилл `/deploy` или раздел «Прод» в CLAUDE.md.

⚠️ Две вещи обычный деплой не везёт:
- **systemd-юниты** — `git pull` обновляет `deploy/*.service`, systemd читает
  `/etc/systemd/system`. После правки юнита: `bash deploy/install-units.sh`
- **nginx-конфиг** — живой файл лежит в `/etc/nginx/sites-available/keybest.cc`
  и правится certbot'ом, поэтому он не копия репозитория. Правки из
  `deploy/nginx-keybest.conf` переносить руками, затем `nginx -t` и
  `systemctl reload nginx`
