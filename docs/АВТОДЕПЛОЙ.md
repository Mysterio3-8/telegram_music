# Автодеплой — как это работает

Коротко: коммит попадает в `main` → GitHub прогоняет тесты → **сервер сам**
раз в 2 минуты смотрит `main` и выкатывает коммит, если тесты по нему зелёные →
отчёт приходит в Telegram.

## Почему так, а не «GitHub заходит на сервер» (15.09)

Раньше выкатку делал GitHub Actions по SSH. Шаг «Выкатка на VPS» падал **во всех
25 прогонах с 08.09** при зелёных тестах, и все выкатки шли руками. Входящий SSH
с раннеров GitHub ненадёжен по природе: их адреса меняются, у хостера бывала
петля маршрутизации, на сервере fail2ban. Теперь сервер сам ходит наружу по
HTTPS: ни ключей, ни секретов в GitHub, ни входящих соединений.

## Как устроено

| Где | Что |
|---|---|
| [.github/workflows/deploy.yml](../.github/workflows/deploy.yml) | только job `tests` на каждый пуш в main |
| [deploy/tg-music-pull-deploy.timer](../deploy/tg-music-pull-deploy.timer) | тик раз в 2 минуты после конца прошлого |
| [deploy/pull-deploy.sh](../deploy/pull-deploy.sh) | решает, выкатывать ли |
| [deploy/ci_verdict.py](../deploy/ci_verdict.py) | читает вердикт тестов из API GitHub |
| [deploy/remote-deploy.sh](../deploy/remote-deploy.sh) | сама выкатка: код → pip → миграции → юниты → рестарт → здоровье → 90 сек наблюдения → откат |

Решение на каждом тике:
1. `main` на GitHub = прод → молча выходим.
2. Этот коммит уже падал на выкатке (`/var/lib/tg-music-deploy/failed`) → не
   повторяем. Иначе была бы петля «деплой → откат» каждые 2 минуты.
3. Прод впереди `main` (ручная выкатка) → назад не катимся.
4. Тесты по **этому** коммиту: идут → ждём; красные → не выкатываем и пишем в
   Telegram; не пришли за час → пишем в Telegram один раз.
5. Зелёные → `remote-deploy.sh` **из нового коммита** с точным `DEPLOY_REF`.

⚠️ Засчитываются только проверки приложения `github-actions` — чужое приложение
с правом checks:write выкатку не разрешит.
⚠️ Имя job `tests` — контракт. Переименуешь в workflow — сервер будет ждать.
⚠️ Репозиторий публичный: API читается без токена (60 запросов в час на IP, тик
ходит в API только пока есть невыкаченный коммит).

## Журнал и ручное управление (на сервере)

```bash
tail -20 /var/lib/tg-music-deploy/history.log           # решения автодеплоя
journalctl -u tg-music-pull-deploy -n 100 --no-pager    # полный вывод выкаток
PULL_DEPLOY_DRY=1 bash /opt/tg-music-bot/deploy/pull-deploy.sh   # что бы он сделал
bash /opt/tg-music-bot/deploy/remote-deploy.sh           # выкатить main руками
systemctl disable --now tg-music-pull-deploy.timer       # выключить автодеплой
```

Повторить упавший коммит: убрать его строку из `/var/lib/tg-music-deploy/failed`.
Ручной и автоматический деплой делят замок `/run/tg-music-deploy.lock` — два
разом не пойдут.

## Чего автодеплой НЕ делает — и почему

⚠️ **Не откатывает миграции базы.** Откатывается только код и пакеты.
`alembic downgrade` умеет удалять колонки вместе с данными — ночью, без человека,
это опаснее самой поломки. Если код не заводится с новой схемой, приходит
тревога.

⚠️ **Не поднимает массовый парсер.** Выключенные решением владельца юниты
деплой не трогает.

⚠️ **Не чинит сервер.** Недоступен GitHub — тик тихо пропускается и повторяется
через 2 минуты. Разбор сервера — `bash deploy/triage.sh`.

## Если что-то пошло не так

| Что видите | Что это значит | Что делать |
|---|---|---|
| В Actions красный крестик на «Тесты» | Код не прошёл проверку, на прод НЕ уехал | Прод жив. Сказать мне |
| В Telegram «🔴 тесты красные — НЕ поехал» | То же, сервер это увидел | Прод жив. Сказать мне |
| В Telegram «⚠️ тесты не пришли за час» | Workflow не запустился или завис | Вкладка Actions |
| В Telegram «🔴 Деплой сломал, откатил» | Новый код не завёлся, вернули старый | Прод жив на старой версии. Сказать мне |
| В Telegram «🔴🔴 откат НЕ помог» | Дело не в коде — сервер или база | На сервере: `bash deploy/triage.sh` |
