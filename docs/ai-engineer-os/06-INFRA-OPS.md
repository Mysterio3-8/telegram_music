# 06 — ИНФРАСТРУКТУРА И ЭКСПЛУАТАЦИЯ

---

## §1. Конфигурация (A02 — вторая по частоте категория OWASP 2025)

- [ ] Все настройки — из окружения, с валидацией на старте
- [ ] Приложение **не стартует** с пустым критичным секретом вместо тихого фолбэка
- [ ] Разные значения для dev и прод; дефолты безопасны
- [ ] Отладочный режим выключен на проде
- [ ] Лишние порты закрыты, лишние сервисы выключены
- [ ] Права на файлы и каталоги минимальны
- [ ] В окружении нет ключей, которых код не читает (мусор путает при диагностике)
- [ ] Задокументировано, какой фолбэк у каждого необязательного параметра

---

## §2. Процессы и лимиты ресурсов

- [ ] Лимит памяти задан **после проверки**, влезает ли в него процесс.
      Лимит меньше реального потребления превращает автоперезапуск из защиты в
      генератор нагрузки: каждый заход — полный импорт приложения, круглосуточно
- [ ] Есть мягкий порог до жёсткого предела
- [ ] Ограничено число попыток перезапуска за окно времени
- [ ] Процесс, падающий по неустранимой причине (отозванный токен, битая
      конфигурация), выходит специальным кодом и **не перезапускается**
- [ ] Модель параллелизма соответствует лимиту: несколько процессов внутри
      лимита на один — не влезут
- [ ] Понятно, какие сервисы включены осознанно, а какие выключены осознанно

**Правило.** `Restart=always` защищает от случайного падения, но не от
систематического. Систематическое падение с автоперезапуском — это нагрузка,
а не отказоустойчивость.

---

## §3. Деплой

- [ ] Деплой описан одной командой/скриптом
- [ ] Указано, что **не** доезжает обычным деплоем (конфиги системных служб,
      конфиг веб-сервера, файлы, которые правит другой инструмент) и как их обновлять
- [ ] Миграции применяются до перезапуска приложения
- [ ] Порядок перезапуска сервисов определён
- [ ] Проверка после деплоя автоматическая, а не «посмотрел глазами»
- [ ] Откат возможен и проверен

**Ловушка.** Файл в репозитории и живой файл на сервере — разные вещи, если
живой правит кто-то ещё (например, инструмент выпуска сертификатов). Такой файл
надо править руками и держать бэкапы.

---

## §4. Наблюдаемость (A09)

Различать:

```
Логи     — что произошло, подробно, для разбора
Метрики  — сколько и как быстро, для трендов
Алерты   — что требует вмешательства прямо сейчас
```

Логировать: ошибки с трассировкой, действия администраторов, события
аутентификации, денежные операции, критичные операции, отказы внешних сервисов.

**Не логировать:** токены, пароли, ключи, JWT, cookies, заголовки авторизации,
содержимое персональных данных сверх необходимого.

- [ ] Уровни логов осмысленны; на проде не сыплется отладка
- [ ] Логи ротируются и ограничены по объёму (переполнение диска роняет всё)
- [ ] По логу можно ответить: что, где, когда, у кого
- [ ] Медленные операции видны (замер времени обработки)
- [ ] Наблюдается размер очередей и свободное место на диске

---

## §5. Алерты

Алерт должен срабатывать **раньше**, чем это заметит пользователь.

Минимальный набор:

```
[ ] Сервис не запущен / упал
[ ] Сервис активен, но работа стоит (очередь не убывает — systemd считает это нормой)
[ ] Диск заполняется
[ ] Память на пределе
[ ] Рост ошибок 5xx
[ ] Отказ внешнего источника (все узлы/прокси мертвы)
[ ] Остался последний рабочий узел из нескольких
[ ] Ошибки платежей
```

- [ ] У алертов есть антиспам, иначе их перестают читать
- [ ] Молчание алерта означает «проверено и в порядке», а не «проверка сломана»
- [ ] Предупреждение о «последнем оставшемся» есть — ждать, пока умрут все,
      значит узнать об этом последним

---

## §6. Надёжность

- [ ] Таймауты на **каждом** внешнем вызове
- [ ] Повторы с нарастающей паузой, ограниченные по числу
- [ ] Понятно, что делает система при недоступности каждой зависимости
- [ ] Необязательная зависимость (кэш, отпечатки, метрики) не роняет основной сценарий
- [ ] Обязательная зависимость отказывает явно и заметно
- [ ] Проверка живости и готовности процесса
- [ ] Корректное завершение: незаконченная работа не теряется молча

**Повтор сам может стать аварией.** Несколько сервисов, повторяющих запросы друг
к другу, создают лавину. Ограничивать число попыток и разносить их во времени.

---

## §7. Бэкап и восстановление

«Бэкап включён» — не ответ. Ответ — «восстановление проверено такого-то числа».

- [ ] Снимок делается по расписанию и консистентно (не копированием живого файла)
- [ ] Ротация, чтобы бэкапы не забили диск
- [ ] **Копия вне этого сервера.** Бэкап рядом с базой не переживёт потерю машины
- [ ] Восстановление проверено на практике
- [ ] Известны целевые значения: сколько данных допустимо потерять и за сколько восстановиться
- [ ] Перед разрушительной операцией снимается отдельный снимок

### План восстановления с нуля

Записан и проверен по шагам:

```
Новый сервер → зависимости → код → конфигурация и секреты → восстановление БД
→ восстановление файлов → DNS → сертификат → веб-сервер → службы
→ вебхуки и внешние интеграции переподключены → проверки → прод
```

- [ ] Где лежат: код, конфигурация, секреты, база, файлы, бэкапы — записано
- [ ] Восстановление не зависит от памяти одного человека

---

## §8. CI/CD

```
Коммит → линт → типы → тесты → проверки безопасности → сборка → деплой → проверка → наблюдение
```

- [ ] Красные тесты блокируют деплой
- [ ] Проверка зависимостей на уязвимости в конвейере
- [ ] Секреты в конвейере — из хранилища секретов
- [ ] Сторонние шаги закреплены по версии
- [ ] Есть быстрый откат
- [ ] Тесты проходят на всех платформах, где их запускают (в т.ч. на машине разработчика)

---

## §9. Соседство на сервере

Если машина общая с другими проектами — это часть модели отказов.

- [ ] Известно, кто ещё живёт на машине и сколько потребляет
- [ ] При симптоме «сервер недоступен» первым делом смотрится общая нагрузка,
      а уже потом ищется причина у себя
- [ ] Свои процессы не занимают ресурс целиком

---

## §10. Чек-лист аудита инфраструктуры

```
[ ] Конфигурация валидируется на старте, отладка выключена
[ ] Лимиты памяти проверены замером, автоперезапуск ограничен
[ ] Деплой воспроизводим; известно, что им не доезжает
[ ] Логи без секретов, ротируются
[ ] Алерты покрывают минимальный набор §5
[ ] Таймауты и повторы на всех внешних вызовах
[ ] Бэкап вне сервера, восстановление проверено
[ ] План восстановления записан
[ ] CI блокирует деплой при красных тестах
[ ] Соседи по машине учтены
```
