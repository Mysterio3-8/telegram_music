# 04 — ПРОФИЛЬ: TELEGRAM BOT + MINI APP

Специфика платформы. Сверено с [core.telegram.org/bots/webapps](https://core.telegram.org/bots/webapps).

---

## §1. initData — единственная точка входа доверия в Mini App

Документация Telegram говорит прямо: **данные из этого поля доверять нельзя;
использовать только на сервере бота и только после валидации.**

### Алгоритм проверки (HMAC, свой бот)

```
1. secret_key = HMAC_SHA256(key="WebAppData", msg=bot_token)
2. data_check_string = все полученные поля кроме hash,
   отсортированные по алфавиту, в виде key=<value>,
   склеенные символом \n (0x0A)
3. hex(HMAC_SHA256(data_check_string, secret_key)) == hash
```

### Алгоритм проверки (Ed25519, сторонний сервис без токена бота)

```
data_check_string = "<bot_id>:WebAppData" + \n + все поля кроме hash и signature,
                    отсортированные по алфавиту
Ed25519_verify(public_key, data_check_string, signature)
```

Нужен, если проверяющая сторона не должна знать токен бота.

### Обязательные проверки

- [ ] Подпись сверяется на сервере. Никогда на клиенте.
- [ ] Сравнение хэшей — постоянное по времени (`compare_digest`).
- [ ] **`auth_date` проверяется на свежесть — ПОСЛЕ проверки подписи.**
      Подпись подтверждает, что строку выдал Telegram, но не говорит когда.
      Без этой проверки перехваченная `initData` (лог, скриншот, чужое
      устройство) годится бессрочно и позволяет бесконечно выпускать токены на
      чужой аккаунт.
- [ ] Окно свежести выбрано осознанно. Mini App получает `initData` один раз при
      открытии и переиспользует её при истечении своего JWT — слишком короткое
      окно отрежет человека с давно открытым приложением. Разумно — часы или сутки,
      но не «бессрочно».
- [ ] `user.id` берётся из проверенной `initData`, а не из тела запроса.
- [ ] Поля профиля (`username`, `first_name`, `photo_url`) считаются
      **отображаемыми данными, а не идентификатором**. Их пользователь меняет сам.
- [ ] Отсутствие `hash` — отказ, а не «пропустим проверку».
- [ ] Пустой/дефолтный секрет подписи JWT — отказ на старте приложения, а не тихий фолбэк.

### Тесты, которые обязаны существовать

```
[ ] Валидная initData → успех
[ ] Испорченный hash → отказ
[ ] Подменённый user.id при валидном hash → отказ (хэш не сойдётся)
[ ] Просроченный auth_date при валидном hash → отказ
[ ] Подделанный auth_date → отказ (проверка идёт после подписи)
[ ] Отсутствующий hash → отказ
```

## §2. Токен бота

- [ ] Токен только в окружении, не в коде и не в git
- [ ] Токен не попадает в логи (в т.ч. в URL запросов к Bot API при отладке)
- [ ] Токен не уходит во фронтенд ни в каком виде
- [ ] Понятно, что делать при отзыве токена (см. §6 — `file_id`)

**Утечка токена = полный контроль над ботом:** чтение сообщений, рассылка от
имени бота, подмена контента. Реакция — только перевыпуск у BotFather.

---

## §3. Webhook

- [ ] Секретный путь или `secret_token` — иначе апдейты подделает кто угодно
- [ ] Проверяется, что запрос пришёл от Telegram (секрет в заголовке / список сетей)
- [ ] Тело валидируется как недоверенное
- [ ] Обработка идемпотентна: Telegram повторяет доставку при таймауте
- [ ] Ответ отдаётся быстро; тяжёлая работа уходит в очередь
- [ ] Ошибка обработки не приводит к бесконечным повторам
- [ ] Только HTTPS

Для polling: **два процесса с одним токеном конфликтуют.** Нельзя запускать
локального бота, пока работает прод.

## §4. Апдейты как недоверенный вход

- [ ] `callback_data` — недоверенная строка. Проверять формат и права **на каждое** нажатие.
      Кнопка «удалить трек id=5» из старого сообщения не даёт права удалить трек 5.
- [ ] Лимит `callback_data` — 64 байта. Длинные данные (URL, запрос) — через FSM/БД по индексу,
      а не пихать в кнопку.
- [ ] Deep-link (`?start=...`) — недоверенный параметр. Валидировать, ограничивать длину.
      Реферальная привязка — только один раз (write-once), иначе накрутка.
- [ ] Inline-запрос приходит **на каждое нажатие клавиши**: любая тяжёлая работа
      здесь — свой собственный флуд к Bot API и `429` в ответ. Нужен бюджет обращений и кэш.
- [ ] Сообщения из групп: проверять тип чата и права; не отвечать на всё подряд.
- [ ] Пользователь мог заблокировать бота: `TelegramForbiddenError` — нормальный
      исход, помечать и не долбить.
- [ ] Неизвестная команда обрабатывается, а не роняет обработчик.
- [ ] Глобальный обработчик ошибок: исключение в любом хендлере пишется с
      трассировкой в лог, пользователь получает внятный ответ, а не тишину.

## §5. Флуд и лимиты Bot API

Telegram сам ограничивает бота, и превышение бьёт по всем пользователям сразу.

- [ ] Антифлуд стоит **первым** в цепочке мидлварей — до БД, до проверок, до поиска
- [ ] Есть жёсткий потолок «действий в секунду» отдельно от мягкого интервала
- [ ] Заблокированные попытки тоже считаются
- [ ] Предупреждение — один раз на серию
- [ ] Счётчики антифлуда убираются по неактивности (иначе память течёт)
- [ ] Антидубль по конкретному действию: пока нажатие в работе, повторные тапы не плодят задачи
- [ ] Рассылка идёт с ограничением темпа, а не «в цикле по всем»
- [ ] `429` от Bot API обрабатывается с ожиданием, указанным Telegram

## §6. Файлы и `file_id`

- [ ] **`file_id` принадлежит боту, который загрузил файл.** Смена токена делает
      все накопленные `file_id` мёртвыми. Если каталог держится на них — он
      перестанет отдаваться целиком.
- [ ] Есть архивная копия или механизм самолечения: поймали отказ → погасили
      мёртвый id → поставили задачу на восстановление
- [ ] Самолечение работает **во всех** ветках выдачи, а не только в главной
- [ ] Там, где отправляет Telegram (inline), об отказе не сообщают — живость
      проверяется **до** выдачи, дешёвой проверкой, с кэшем вердиктов и бюджетом
- [ ] Гашение id безопасно: не делать этого там, откуда файл нельзя перезакачать
- [ ] Архивный чат — канал, где бот администратор. Личка человека — плохой архив:
      бот не может писать тому, кто не нажимал `/start`, а человек может заблокировать бота
- [ ] Публичность архивного канала осознана: каждый файл там — видимый пост

---

## §7. Смена токена / переезд бота — что ломается

Список проверяется руками после каждой смены токена:

```
[ ] Все накопленные file_id мертвы → механизм восстановления работает
[ ] Архивный чат: новый бот может туда писать
[ ] Каналы обязательной подписки: новый бот — администратор в каждом
      (иначе fail-closed запирает всех пользователей)
[ ] Кнопка Mini App выставлена (set_chat_menu_button)
[ ] Команды бота и их scope выставлены заново
[ ] Реферальные ссылки, deep-link'и, return_url платежей содержат новый username
[ ] Старый бот отвечает указателем «мы переехали» (пока токен действителен)
```

---

## §8. Обязательная подписка (гейт)

- [ ] При добавлении канала проверяется, что **бот** является его администратором,
      а не то, подписан ли добавляющий
- [ ] Пустой список каналов = гейт выключен (осознанное поведение, не авария)
- [ ] Результат проверки кэшируется с TTL
- [ ] **Сбой Telegram API ≠ «не подписан».** Разводить три исхода: подписан /
      не подписан / спросить не удалось. Последний **не кэшировать**: один сетевой
      сбой иначе запирает подписанного человека на весь TTL, а гейт пропускает
      только `/start`
- [ ] Fail-closed сохранён, но с опорой на прежний вердикт, если он есть
- [ ] Первый экран новичка (гейт) переведён на все поддерживаемые языки — он
      показывается **раньше** любого выбора языка

## §9. Mini App: платформенные особенности

- [ ] Работает в iOS, Android, Telegram Desktop, Web
- [ ] Тема берётся из Telegram (светлая/тёмная), не захардкожена
- [ ] Кнопка «Назад» и жест «свайп вниз» не ломают навигацию
- [ ] Вертикальные свайпы отключены там, где мешают
- [ ] Подтверждение закрытия, если есть несохранённое
- [ ] `CloudStorage` / `localStorage` могут быть недоступны — код работает без них
- [ ] Воспроизведение медиа: поведение в фоне и при возврате проверено на живом устройстве
- [ ] Внешний домен Mini App: репутация домена в Safe Browsing проверяется —
      предупреждение браузера отрезает часть аудитории целиком
- [ ] Веб-сервер не отдаёт `200` на любой путь: несуществующий → `404`.
      Иначе сканеры видят профиль фишинг-кита, и домен получает репутационный удар
- [ ] Страница без JS отдаёт осмысленное описание, а не пустой контейнер

---

## §10. Чек-лист аудита Telegram-профиля

```
[ ] initData: подпись + свежесть (в этом порядке), тесты на подделку
[ ] Личность только из проверенной initData
[ ] Токен бота нигде не утекает
[ ] Webhook: секрет, идемпотентность, быстрый ответ
[ ] callback_data и deep-link проверяются как недоверенный вход
[ ] Права на каждое нажатие, не только при показе кнопки
[ ] Антифлуд первым в цепочке, счётчики убираются
[ ] file_id: самолечение во всех ветках, архив в канале
[ ] Гейт подписки: бот-админ, сбой ≠ отказ, вердикт сбоя не кэшируется
[ ] Mini App: все платформы, тема, навигация, отсутствие storage
[ ] Домен: 404 на несуществующее, репутация проверена
[ ] Смена токена: список §7 пройден
```
