# 05 — ДЕНЬГИ

Отдельный модуль, потому что здесь ошибка стоит не «неудобно», а «потеряли
деньги» или «взяли лишнее у человека».

---

## §1. Правило нуля доверия к клиенту

Клиент сообщает **что он хочет купить**, а не **сколько это стоит**.

- [ ] Сумма берётся из серверного справочника тарифов по идентификатору тарифа
- [ ] Срок/количество берутся оттуда же
- [ ] Скидка вычисляется сервером; потолок скидки задан константой
- [ ] Валюта задаётся сервером
- [ ] Отрицательные и нулевые суммы отклоняются
- [ ] Сумма, пришедшая от платёжной системы, **сверяется** с ожидаемой перед выдачей товара

---

## §2. Текст цены — часть платежа

Классическая ошибка: сумма и срок в сообщении пользователю захардкожены под
один тариф, а списывается другой. Платёж корректен, врёт только текст — и это
всё равно обман пользователя.

- [ ] Сумма, срок и название тарифа в тексте формируются из тех же данных, что и платёж
- [ ] Скидка видна пользователю до оплаты
- [ ] Итоговая цена показана до подтверждения, а не после списания

---

## §3. Вебхук платёжной системы

- [ ] Подлинность запроса проверяется (подпись/секрет/список адресов)
- [ ] **Телу вебхука не верят на слово**: статус платежа перепроверяется отдельным
      запросом к API платёжной системы
- [ ] Сверяется: статус, сумма, валюта, пользователь, идентификатор заказа
- [ ] Идемпотентность: повторная доставка не выдаёт товар второй раз
- [ ] Ключ идемпотентности — идентификатор платежа, а не время получения
- [ ] Быстрый ответ; тяжёлое — в очередь
- [ ] Все ветки логируются: пришло, проверено, выдано / отклонено и почему
- [ ] Неизвестный статус не считается успехом

---

## §4. Журнал операций

- [ ] Каждая денежная операция пишется в отдельную таблицу-журнал
- [ ] Журнал только пополняется; корректировка — новой записью, не правкой старой
- [ ] По журналу можно восстановить: кто, когда, сколько, за что, каким способом, чем закончилось
- [ ] Выручка считается по журналу, а не по флагу в профиле пользователя
- [ ] Расхождение журнала и состояния пользователя обнаруживается сверкой

---

## §5. Подписки и автопродление

- [ ] Активность подписки определяется **по сроку**, а не по булеву флагу.
      Истёкший флаг безвреден только если все проверки идут через функцию «активна ли»
- [ ] Срок продлевается от большего из «сейчас» и «текущий конец», а не от «сейчас» всегда
- [ ] Автопродление отключается пользователем в один шаг
- [ ] Неудачное списание не отключает доступ мгновенно без уведомления
- [ ] Повторная попытка списания ограничена по числу
- [ ] Живой рекуррент проверяется **реальной картой** — тестом это не покрывается

---

## §6. Возвраты и споры

- [ ] Есть понятная процедура возврата (даже если ручная)
- [ ] Возврат снимает выданное или явно решено, что не снимает
- [ ] Возврат отражается в журнале
- [ ] Условия возврата описаны в оферте

---

## §7. Награды, бонусы, рефералы — тоже деньги

Всё, что конвертируется в платный доступ, атакуется так же, как деньги.

- [ ] Награда выдаётся один раз (идемпотентно), проверено на гонке
- [ ] Порог считается по «живым» участникам, а не по факту регистрации
- [ ] Привязка реферала — write-once, переприкрепление невозможно
- [ ] Заблокировавшие бота не учитываются
- [ ] Пороги и величины наград приходят с сервера в единственном экземпляре;
      копия списка на клиенте — источник расхождений в цифрах
- [ ] Множители применяются в одном месте; проверено, что после множителя
      первый порог не превращается в ноль

---

## §8. Чек-лист аудита денег

```
[ ] Цена, срок, валюта — только с сервера
[ ] Текст пользователю совпадает со списанием
[ ] Вебхук: подлинность + перепроверка у API + идемпотентность
[ ] Сумма сверяется перед выдачей товара
[ ] Журнал операций ведётся и по нему считается выручка
[ ] Активность подписки — по сроку, через единую функцию
[ ] Награды идемпотентны и защищены от накрутки
[ ] Пороги наград — из одного источника
[ ] Живой платёж проверен реальной картой
[ ] Оферта и условия возврата опубликованы
```
