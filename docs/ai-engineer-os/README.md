# AI Engineer OS

Свод инженерных правил, по которым ведётся разработка этого проекта.
Написан как **исполняемый протокол для ИИ-агента**, а не как справочник для чтения.

## Зачем это существует

ИИ хорошо пишет то, что видно: экраны, кнопки, «счастливый путь». Плохо — то,
чего не видно: авторизация на уровне ресурса, гонки, повторные вебхуки, лимиты,
восстановление после сбоя. Продукт при этом выглядит готовым.

Этот свод превращает невидимое в обязательный чек-лист с гейтами: **нельзя
объявить работу готовой, пока соответствующие проходы не выполнены или явно не
помечены `UNKNOWN`.**

## Как этим пользоваться

**Владельцу.** Достаточно сказать: «пройди аудит N» или «прогони блок SECURITY».
Результат — не рассказ, а обновлённый `PROJECT-STATUS.md` с исправлениями в коде
и новыми тестами.

Присланный материал (статья, доклад, чужой чек-лист) обрабатывается по
[INTAKE.md](INTAKE.md): материал → проверка по первоисточнику → правило в свод →
проход проекта по новому правилу → исправление → тест. Знать, что именно
присылать, не требуется — разбор на применимое и неприменимое делается здесь.

**ИИ-агенту.** Порядок работы:

```
Задача
  ↓
00-CORE §1 (границы доверия) + профильный модуль
  ↓
Реализация
  ↓
Проходы самопроверки 00-CORE §5 (минимум 1,2,3,5)
  ↓
Тесты на каждую найденную дыру
  ↓
Обновить PROJECT-STATUS.md и LESSONS.md
  ↓
PRODUCTION-CHECKLIST перед деплоем
```

## Железное правило

Если проверку выполнить не удалось — в отчёте пишется `UNKNOWN` с причиной.
**`PASS` без выполненной проверки — ложь и запрещён.**
