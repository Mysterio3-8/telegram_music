# НАКОПЛЕННЫЕ УРОКИ

Каждая запись: симптом → корневая причина → почему это было допущено →
универсальное правило → тест. Правило без теста забывается; тест без правила не
переносится на другие места.

Новые записи — сверху.

---

## 2026-09-08 · Защита от повтора, привязанная к текущему состоянию

**Симптом:** проверка «этот платёж уже обработан» выглядит рабочей и на первом
платеже работает.

**Корневая причина:** идемпотентность реализована сравнением с **последним**
применённым платежом (`subscription.payment_id == payment.id`), а не фактом
«этот идентификатор уже применялся». Второй платёж затирает состояние, и повтор
первого проходит защиту насквозь.

**Почему допущено:** проверялся счастливый путь «один пользователь — один
платёж». Сценарий «второй платёж, потом повтор первого» не рассматривался.

**Универсальное правило:** ключ идемпотентности хранится в **журнале
применённых операций** с уникальным ограничением. Состояние объекта —
не ключ идемпотентности: оно перезаписывается.

**Тест:** применить платёж A, применить платёж B, повторно применить A →
эффект не должен возникнуть второй раз.

## 2026-08-17 · Подпись подтверждает происхождение, но не время

**Симптом:** перехваченная `initData` годилась бессрочно.

**Корневая причина:** сверялась подпись, но не `auth_date`.

**Универсальное правило:** подпись отвечает на вопрос «кто выдал», а не «когда».
Свежесть — отдельная проверка, и она обязана идти **после** проверки подписи,
иначе поле времени подделывается.

**Тест:** просроченная метка при валидной подписи → отказ; подделанная метка → отказ.

## 2026-08-16 · Незнание работало преимуществом

**Симптом:** в выдаче наверх выходил малоизвестный кандидат.

**Корневая причина:** объекту без счётчика популярности подставлялся его же
текстовый счёт — то есть «раз похож на запрос, значит и популярен».

**Универсальное правило:** различать `None` («источник не сказал») и `0`
(«источник сказал: ноль»). Отсутствие данных заменяется нейтральной серединой,
а не благоприятным значением.

## 2026-08-16 · Молчаливый отказ внешнего узла

**Симптом:** функция «иногда не работает».

**Корневая причина:** узел был мёртв, а код возвращал пустой результат —
неотличимо от «ничего не найдено».

**Универсальное правило:** отказ обязан быть отличим от пустоты и обязан быть
заметен. Флаги библиотек вида «игнорировать ошибки» выключать. Проверка живости
должна брать **весь** список ресурсов, а не план ближайших попыток.

**Тест/механика:** периодическая проверка с алертом; отдельное предупреждение,
когда живым остался последний узел.

## 2026-08-16 · Автоперезапуск как генератор нагрузки

**Симптом:** четверть ядра съедал сервис, который «просто перезапускается».

**Корневая причина:** процесс падал при старте по неустранимой причине
(отозванный токен), а `Restart=always` поднимал его снова — сотни раз.

**Универсальное правило:** неустранимая ошибка конфигурации → выход специальным
кодом и запрет перезапуска. Плюс потолок числа перезапусков за окно.
Лимит памяти задаётся после проверки, влезает ли в него процесс.

## 2026-08-16 · Сбой внешнего API, записанный в кэш как отрицательный ответ

**Симптом:** подписанный человек оказывался заперт во всём боте.

**Корневая причина:** «не подписан» и «спросить не удалось» возвращались одним
значением, и оно кэшировалось на весь TTL.

**Универсальное правило:** три исхода вместо двух: да / нет / не удалось спросить.
Последний **не кэшируется**. Fail-closed сохраняется, но с опорой на прежний
вердикт, если он есть.

## 2026-08-16 · Периодический перебор без отметки «уже занимались»

**Симптом:** ночная задача работала и рапортовала, но результат не рос.

**Корневая причина:** условие выборки кандидатов никогда не переставало
выполняться, отметки об обработке не было — бюджет уходил в повторы.

**Универсальное правило:** у любого периодического перебора есть отметка
обработки, она ставится **до** попытки (процесс могут убить посередине), и в
сводке есть строка «осталось в очереди» — по ней видно остановку.

## 2026-08-16 · SQLite `lower()` не понижает кириллицу (третий раз)

**Симптом:** дедуп не находил очевидные дубли.

**Корневая причина:** сравнение шло через `lower()` в SQL против понижённой в
Python строки. SQLite понижает только ASCII.

**Универсальное правило:** любое сравнение строк с пользовательским текстом —
по нормализованной в Python колонке, а не через `lower()`/`ilike` в запросе.
Прежнее сравнение оставляется фолбэком, а не выбрасывается.

**Цена повторения:** тот же баг ломал поиск, привязку артистов и дедуп — три
разных места, один принцип.

## 2026-08-11 · Остановленный сервис systemd считает здоровым

**Симптом:** задачи ставились в очередь и не выполнялись.

**Корневая причина:** воркеры были остановлены руками; `Restart=always` от этого
не спасает — остановку командой systemd считает волей администратора.
Очередь росла молча.

**Универсальное правило:** наблюдать не «процесс жив», а «работа движется».
Очередь, которая не убывает при активном сервисе, — авария.

## 2026-08-04 · Веб-сервер отдавал 200 на любой путь

**Симптом:** предупреждение браузера о небезопасном сайте, отрезавшее часть аудитории.

**Корневая причина:** фолбэк на главную страницу отдавал `200` и HTML на
несуществующие пути — в логах полторы тысячи сканерных проб с успешным кодом.
Профиль сайта выглядел как фишинг-кит.

**Универсальное правило:** несуществующий путь → `404`. Искать причину
репутационных проблем надо в **поведении веб-сервера**, а не только в контенте.

## 2026-08-02 · Защита данных пользователей при массовом удалении

**Симптом:** чистка каталога по разумному критерию задевала 93% собранного
пользователями.

**Универсальное правило:** перед удалением по критерию посчитать, сколько из
удаляемого лежит в чьих-то библиотеках и плейлистах. Сам объект восстановим,
дыра в чужом плейлисте — нет. Защита включена по умолчанию.
При разборе дублей — **слияние**, а не удаление: связи переносятся, удаляется
только осиротевшая запись.
