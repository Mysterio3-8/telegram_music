# 07 — ЮРИДИЧЕСКИЙ СЛОЙ

⚠️ Это инженерный чек-лист, а не юридическая консультация. Он показывает, **какие
вопросы обязаны быть закрыты** и какие технические механизмы для этого нужны.
Конкретные обязанности перед запуском сверяются с актуальными требованиями и, где
цена ошибки высока, с юристом. ИИ **не имеет права** объявить «всё законно».

---

## §1. Юрисдикция не выбирается доменом

Частое заблуждение: «домен .com — значит не российский проект». Обязанности
определяются не зоной домена, а связкой:

```
Где находятся пользователи      → чьё право о персональных данных применимо
Кто принимает деньги            → налоги, чеки, оферта, требования платёжной системы
Где размещён сервер             → требования к размещению данных
Какой контент раздаётся         → авторское право, порядок реагирования на жалобы
Кто оператор (лицо/компания)    → его резидентство и статус
```

Домен и хостинг влияют на **репутацию и доступность**, а не на применимое право.
Поэтому переезд на `.com` — задача из [06-INFRA-OPS](06-INFRA-OPS.md), а не решение
юридического вопроса.

- [ ] Выписано: где аудитория, кто получатель денег, где сервер, какой контент
- [ ] Для каждой строки определён режим и что он требует
- [ ] Решение зафиксировано в `PROJECT-STATUS.md`, а не держится в голове

---

## §2. Данные: инвентаризация до всякого права

Без этой таблицы невозможно оценить ни один режим. Заполняется всегда:

| Данные | Зачем собираем | Где храним | Сколько храним | Кто имеет доступ | Уходит ли третьим лицам |
|---|---|---|---|---|---|
| … | | | | | |

- [ ] Собирается только необходимое. «Пусть будет» — не основание
- [ ] Срок хранения определён для каждой категории
- [ ] Известно, какие данные уходят наружу (платёжка, аналитика, внешние API, CDN)
- [ ] Логи и бэкапы включены в инвентаризацию — про них забывают
- [ ] Есть техническая возможность найти все данные одного человека
- [ ] Есть техническая возможность их удалить или обезличить

---

## §3. Обязательные документы и механизмы

Независимо от юрисдикции продукт с пользователями и деньгами нуждается в:

- [ ] Политика обработки данных: что, зачем, сколько, кому, как удалить
- [ ] Пользовательское соглашение / оферта: что за услуга, цена, срок, порядок отказа и возврата
- [ ] Контакт для обращений — рабочий, а не декоративный
- [ ] Раскрытие: сервис не связан с Telegram и не является его частью
- [ ] Возрастная политика, если контент или платежи это требуют
- [ ] Реквизиты получателя платежей
- [ ] Документы доступны **до** оплаты, а не после
- [ ] Согласие на списание при автопродлении получено явно, с указанием суммы и периодичности

---

## §4. Права пользователя — как технические функции

Юридические формулировки различаются, набор механизмов — почти одинаковый.
Их надо **реализовать**, а не описать:

```
[ ] Показать, какие данные о человеке есть
[ ] Экспортировать их в машинном виде
[ ] Исправить
[ ] Удалить аккаунт: профиль, файлы, сессии, токены, связанные записи
[ ] Отозвать согласие (в т.ч. на рассылки и автосписание)
[ ] Отказаться от рассылки одним действием
```

При удалении аккаунта решить и записать:
что удаляется физически, что обезличивается, что остаётся по обязательным
причинам (журнал платежей), и что происходит с бэкапами.

## §5. Режимы по регионам — что меняется

### Аудитория в РФ / платежи через российскую платёжную систему

- Обработка персональных данных требует статуса оператора и **уведомления
  регулятора о намерении обрабатывать данные**. С 30 мая 2025 года за
  неуведомление предусмотрен штраф, в том числе для физлиц и самозанятых
  ([Контур](https://www.kontur-extern.ru/info/25487-kto_i_kogda_dolzhen_uvedomit_roskomnadzor_ob_obrabotke_personalnyx_dannyx)).
  Сведения в уведомлении обновляются при изменениях.
- Требования к размещению данных, оферте, чекам, рекламе, возрасту — сверять отдельно.
- Статус получателя денег (самозанятый / ИП / организация) определяет налоговые обязанности.

⚠️ Сверить с первоисточником перед действием: нормы менялись в 2024–2025 годах,
и в этом файле они приведены как ориентир, а не как актуальная выжимка.

### Аудитория в ЕС

- Нужны: правовое основание обработки, политика, реализованные права субъекта (§4),
  сведения о передаче данных за пределы региона, порядок действий при утечке.
- Аналитика и трекеры без согласия — отдельный риск.

### Аудитория в США

- Ключевое практическое: возрастные ограничения для детской аудитории,
  прозрачность подписки и порядок её отмены, правила магазинов приложений (если появятся).

### Общее при переезде на западную инфраструктуру

- [ ] Платёжная система: её требования к товару и контенту часто **строже** закона.
      Музыкальный сервис без прав на каталог — типовая причина отказа в обслуживании
- [ ] Хостинг и домен: правила провайдера по контенту
- [ ] Процедура реагирования на жалобы правообладателей — контакт, срок, порядок снятия

---

## §6. Контент и авторское право — главный риск именно этого класса продуктов

Для сервиса, раздающего музыку, это **основной** юридический риск, крупнее
персональных данных.

- [ ] Определено, на каком основании раздаётся каждый вид контента
- [ ] Есть рабочий канал для обращений правообладателей и срок реакции
- [ ] Есть техническая возможность быстро снять конкретный объект и заблокировать повторную заливку
- [ ] Не реализуется обход технических средств защиты — это отдельное нарушение,
      независимое от всего остального
- [ ] Пользовательские загрузки: соглашение переносит ответственность на загружающего,
      есть процедура снятия по жалобе
- [ ] Понятно, что произойдёт при массовой жалобе: план, а не импровизация

## §7. Чек-лист переезда в другую юрисдикцию

```
[ ] Инвентаризация данных обновлена (§2)
[ ] Определены новые применимые режимы (§1, §5)
[ ] Документы переписаны под нового получателя платежей и новую аудиторию
[ ] Платёжная система принимает такой товар — подтверждено до переезда
[ ] Реализованы права пользователя нового режима (§4)
[ ] Процедура реагирования на жалобы по контенту работает
[ ] Домен: проверена репутация до переноса аудитории
[ ] Прежние обязанности закрыты, а не просто оставлены
```

## §8. Чек-лист аудита юридического слоя

```
[ ] Юрисдикции определены по аудитории/деньгам/серверу/контенту, а не по домену
[ ] Инвентаризация данных заполнена, включая логи и бэкапы
[ ] Документы существуют, актуальны и доступны до оплаты
[ ] Права пользователя реализованы технически, а не только описаны
[ ] Обязанности по текущему региону закрыты (или явно UNKNOWN с причиной)
[ ] Канал и процедура для жалоб правообладателей работают
[ ] Требования платёжной системы к товару подтверждены
[ ] Утечка данных: план реагирования есть
```
