# 03 — ФРОНТЕНД И БРАУЗЕРНАЯ БЕЗОПАСНОСТЬ

---

## §1. Главное правило

Фронтенд — это **интерфейс**, а не место, где принимаются решения.

```
ПЛОХО (это не защита):
  if (user.isPremium) { download(); }

ПРАВИЛЬНО:
  Фронт показывает кнопку по своему представлению о правах.
  Сервер при вызове проверяет права заново и отказывает, если их нет.
```

Всё, что попало в браузер, пользователь видит и меняет: код, переменные,
localStorage, тело запроса, заголовки. Скрытое поле, отключённая кнопка,
проверка в JS — не механизмы безопасности.

- [ ] Ни одно правило доступа не существует только на клиенте
- [ ] Цена, срок, скидка, лимит приходят с сервера и им же проверяются
- [ ] Во фронтенде нет секретов: ключей, токенов сервисов, приватных URL

---

## §2. Состояния интерфейса

ИИ по умолчанию рисует один экран — «всё загрузилось и всё хорошо». Обязательны все:

```
[ ] Загрузка          (и она не «прыгает» — скелет вместо пустоты)
[ ] Пусто             (осмысленный текст, а не пустой экран)
[ ] Ошибка            (что случилось и что сделать)
[ ] Нет сети / офлайн
[ ] Медленная сеть    (запрос идёт 10 секунд — интерфейс не выглядит сломанным)
[ ] Частичный отказ   (часть блоков загрузилась, часть нет)
[ ] Повторное действие (кнопка блокируется на время запроса)
[ ] Устаревшие данные (что делать, если ссылка/токен протухли — перезапросить, а не показать ошибку)
```

- [ ] Двойной клик не отправляет две операции
- [ ] Потеря соединения посреди запроса не оставляет интерфейс в подвешенном состоянии
- [ ] Долгая операция показывает прогресс или хотя бы факт работы

---

## §3. Экранирование и XSS

Любой текст, пришедший не от нас, — чужой: имена, названия, описания, ники,
данные из внешних источников.

- [ ] Текст вставляется как текст, а не как HTML
- [ ] Если экранирование самописное — оно закрывает **все** опасные символы,
      включая одинарную кавычку (она нужна, когда значение попадает внутрь
      `url('…')` в атрибуте `style` — оттуда можно выйти из скобок)
- [ ] Значения, попадающие в атрибуты, экранируются по правилам атрибута
- [ ] Значения, попадающие в URL, кодируются
- [ ] Нет вставки чужого HTML/SVG без санитизации
- [ ] Нет `eval` и построения кода из строк

---

## §4. Заголовки и транспорт

- [ ] Только HTTPS, редирект с HTTP
- [ ] `Strict-Transport-Security`
- [ ] `X-Content-Type-Options: nosniff`
- [ ] `Referrer-Policy`
- [ ] `Content-Security-Policy` — там, где применимо (в Mini App проверить, что не ломает Telegram SDK)
- [ ] `Permissions-Policy` для неиспользуемых возможностей
- [ ] CORS настроен по списку источников; `*` для приватного API недопустим
- [ ] Cookies (если есть): `Secure`, `HttpOnly`, `SameSite`
- [ ] Несуществующий путь отдаёт `404`, а не `200` с главной страницей —
      иначе сканеры видят профиль фишинг-кита и домен получает репутационный удар

---

## §5. Хранилище на клиенте

- [ ] В `localStorage` нет ничего, что нельзя показать постороннему
- [ ] Данные с истекающим сроком (подписанные ссылки) **не кэшируются** надолго —
      иначе интерфейс покажет «недоступно» на рабочем ресурсе; при отсутствии/ошибке
      ссылку надо перезапрашивать
- [ ] Код работает, если хранилище недоступно или пустое (приватное окно, очистка, запрет)
- [ ] Каждое обращение к хранилищу обёрнуто в обработку ошибок

---

## §6. Производительность фронтенда

Порядок действий — сначала замер, потом оптимизация. Оптимизация вслепую тратит
время не там.

- [ ] Проверено сжатие ответов сервера. Отсутствие сжатия статики — типовая
      причина «долго грузится»: разница бывает трёхкратной
- [ ] Проверена версия HTTP: на HTTP/1.1 полсотни файлов едут очередями по шесть
- [ ] Модули первого экрана предзагружаются
- [ ] Изображения ужаты и имеют размеры
- [ ] Нет полного перерисовывания экрана на каждое событие (например, на тик прогресса)
- [ ] Длинные списки не рендерятся целиком
- [ ] Позиция прокрутки не сбрасывается при обновлении данных
- [ ] Замер сделан на медленном канале и слабом устройстве, а не только локально

---

## §7. Адаптивность и доступность

- [ ] Узкий экран (360–375 px) — нет горизонтальной прокрутки
- [ ] Планшет и десктоп
- [ ] Тёмная и светлая тема
- [ ] Области нажатия достаточного размера (мелкий ползунок на 4 px не попадается пальцем)
- [ ] Контраст текста читаемый
- [ ] Навигация с клавиатуры не ломается
- [ ] Тексты не обрезаются при длинных названиях и при переводе на другой язык

---

## §8. Мультиязычность

- [ ] Строки вынесены в словари, не захардкожены
- [ ] Наборы ключей всех языков совпадают — это стережёт тест
      (отставший язык молча показывает чужой текст; лишний ключ — след переименования)
- [ ] Цепочка фолбэка определена: выбранный → английский → базовый → сам ключ
- [ ] Формы множественного числа учтены (русскому нужны три)
- [ ] Автоопределение языка и **осознанный выбор** хранятся в разных полях —
      иначе выбор затирается при каждом входе
- [ ] Первый экран новичка переведён (он показывается раньше выбора языка)
- [ ] Списки локалей, продублированные в двух местах, правятся синхронно

---

## §9. Чек-лист аудита фронтенда

```
[ ] Ни одна проверка прав не живёт только на клиенте
[ ] Секретов во фронте нет
[ ] Все состояния экрана реализованы
[ ] Двойной клик безопасен
[ ] Экранирование закрывает все символы, включая одинарную кавычку
[ ] Заголовки безопасности выставлены, CORS не «*»
[ ] Несуществующий путь → 404
[ ] Протухающие ссылки не кэшируются, перезапрашиваются
[ ] Сжатие и версия HTTP проверены замером
[ ] Узкий экран, обе темы, длинные строки
[ ] Наборы ключей локалей совпадают (тест)
```
