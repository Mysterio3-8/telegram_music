# Веб-админка владельца

Открывается **только на компьютере владельца**. Из интернета её нет: на сервере
она слушает `127.0.0.1:8011` и в nginx не заведена.

## Как открыть

```bash
python -m app.webadmin
```

Команда поднимает SSH-туннель до сервера и открывает `http://127.0.0.1:8011/`.
Пропуск — SSH-ключ владельца, пароль вводить негде. Закрыть — Ctrl+C в том же окне.

Флаги: `--local` (страница на локальной БД, для отладки), `--port`, `--no-browser`.

## Что внутри

| Раздел | Что показывает |
|---|---|
| Обзор | Люди, удержание, прослушивания, сессии Mini App, поиски, Premium, деньги, каталог; графики по дням; жанры, топ треков и запросов |
| Люди | Список с поиском по имени, @username и Telegram-id: когда пришёл, Premium, прослушивания, язык, заблокировал ли бота |
| Каталог | Поиск по исполнителю и названию (кириллица и латиница), альбом, длина, настроение, прослушивания, готов ли файл |
| Деньги | Последние оплаты Premium и донаты с отметкой возврата |

Первая версия **только читает**. Правки каталога, выдача Premium, модерация и
рассылки остаются в боте: там к подтверждениям привыкли, и случайный клик мышью
не стоит каталога.

## Почему так, а не страница на домене

В логах домена за одну ротацию **2014 путей сканеров**. У страницы, которой нет
в интернете, поверхности атаки нет вовсе: ни брутфорса пароля, ни утечки, ни
забытой сессии в чужом браузере. Второй рубеж на случай неаккуратного туннеля —
`WEBADMIN_TOKEN` в `.env`: когда задан, без заголовка `X-Admin-Token` данные не
отдаются.

## Сервис на сервере

Юнит `tg-music-webadmin.service` (ставится `bash deploy/install-units.sh`),
`MemoryMax=200M`, `Nice=10` — бот и API важнее. Проверить:
`systemctl status tg-music-webadmin`, логи — `journalctl -u tg-music-webadmin`.
