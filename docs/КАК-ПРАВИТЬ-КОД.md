# Как самому править бота: от VS Code до прода

Короткая инструкция для владельца. Порядок всегда один: **правка → тесты →
коммит → пуш → обновление сервера**. Пропускать шаги нельзя — на сервере живые
пользователи.

## 0. Один раз: открыть проект

В VS Code: `Файл → Открыть папку` → `C:\Users\Илья\Desktop\ТГ музыка`.
Терминал внутри VS Code: `Ctrl+~`.

## 1. Где что лежит

Ищи не глазами по папкам, а поиском по тексту: `Ctrl+Shift+F` и вставь фразу,
которую видел в боте. Так находится почти всё за секунды.

| Что менять | Где |
|---|---|
| Тексты, которые видит человек | [app/i18n/locales/ru.py](../app/i18n/locales/ru.py) — и такой же ключ в остальных шести языках |
| Кнопки и их расположение | [app/keyboards/](../app/keyboards/) |
| Что происходит по нажатию | [app/handlers/](../app/handlers/) |
| Правила и логика (поиск, скачивание, Premium) | [app/services/](../app/services/) |
| Числа и настройки (лимиты, цены, размеры страниц) | [app/config.py](../app/config.py) |
| Внешний вид Mini App | [miniapp/src/](../miniapp/src/) |

Правило проекта: в `handlers/` только «нажали кнопку — позвали функцию»,
вся логика в `services/`. Если пишешь в хендлере расчёты — скорее всего, не туда.

⚠️ **Тексты живут в семи языках.** Добавил ключ в `ru.py` — добавь его и в
`en/es/de/fr/pt/tr`, иначе тест упадёт (он специально стережёт, чтобы у языков
не разъезжались наборы ключей).

## 2. Проверить, что не сломал

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Должно быть `450 passed` (число растёт со временем). **Красный тест — не
деплоить.** Если упал тест, который ты не трогал, значит правка задела что-то
соседнее: читай название теста, там написано, что именно сломалось.

Если менял модели базы (`app/db/models.py`) — нужна миграция:

```powershell
$env:DATABASE_URL="sqlite+aiosqlite:///_tmp.db"; .\.venv\Scripts\python.exe -m alembic upgrade head; .\.venv\Scripts\python.exe -m alembic revision --autogenerate -m "что добавил"; Remove-Item _tmp.db; Remove-Item Env:\DATABASE_URL
```

## 3. Отправить в GitHub

```powershell
git add -A
git commit -m "коротко, что сделал"
git push
```

Сообщение коммита — по-человечески: «убрал кнопку Назад с карточки», а не
«фикс». Через месяц ты сам будешь это читать, разбираясь, когда что сломалось.

## 4. Обновить сервер

Зайти на сервер (`ssh news-rewriter-vps`) и одной командой:

```bash
cd /opt/tg-music-bot && bash deploy/update.sh
```

Скрипт сам заберёт код, поставит зависимости, применит миграции, обновит юниты
и перезапустит сервисы. Останавливается на первой ошибке.

Проверить, что живо:

```bash
systemctl is-active tg-music-bot tg-music-worker tg-music-youtube-user tg-music-api
```

Посмотреть, что бот пишет в логи прямо сейчас:

```bash
journalctl -u tg-music-bot -f
```

(выйти — `Ctrl+C`)

## 5. Если после деплоя стало хуже

Откат делается в GitHub, а не на сервере — иначе следующий `git pull` подерётся
с твоими правками.

На своей машине:

```powershell
git revert HEAD
git push
```

На сервере снова `bash deploy/update.sh`. Через минуту прод как был.

## Чего не делать

- **Не править файлы прямо на сервере.** Источник правды — GitHub; правка на
  сервере переживёт ровно до следующего обновления, а `git pull` будет падать.
- **Не запускать бота локально**, пока работает сервис на VPS: два процесса с
  одним токеном конфликтуют за апдейты Telegram.
- **Не трогать `.env` на сервере** без нужды — там боевые токены и ключи оплаты,
  их нет в репозитории.
- **Не удалять миграции** из `migrations/versions/`, даже старые: база на сервере
  проходит по ним цепочкой.
- **Не коммитить токены и куки.** Всё секретное — только в `.env`.

## Как понять, что твоя правка доехала

Сторож здоровья ([deploy/healthcheck.sh](../deploy/healthcheck.sh)) раз в две
минуты проверяет сервисы и пишет в Telegram, если что-то легло. Молчит — значит
всё поднялось. Проверить его глазами:

```bash
journalctl -u tg-music-health -n 20 --no-pager
```
