# Бэкапы базы и восстановление

Три копии, от ближней к дальней:

| Где | Что | Сколько хранится |
|---|---|---|
| Сервер, `/opt/tg-music-bot/backups/` | снимок SQLite, каждый день в 04:00 UTC | 2 последних (`BACKUP_KEEP`) |
| Telegram владельца | тот же снимок, сжатый и **зашифрованный** (`*.sqlite.gz.enc`) | всегда, в переписке с ботом |
| Компьютер владельца, `Документы\InfinityMusic\backups` | снимок как есть, забирается по SSH, когда компьютер включён | 7 последних |

⚠️ **Пароль шифрования** лежит в `.env` сервера (`BACKUP_PASSWORD`) и в файле
`Документы\InfinityMusic\ПАРОЛЬ-БЭКАПОВ.txt` на компьютере владельца. Если сервер
умер — копия из Telegram расшифровывается только этим паролем. Сохрани его ещё и
в менеджер паролей: компьютер тоже может сломаться.

## Восстановить из Telegram (сервера больше нет)

Нужен `openssl` — он есть в Git Bash на Windows и на любом Linux.

1. Скачай из переписки с ботом файл `infinity-db-ГГГГ-ММ-ДД.sqlite.gz.enc`.
2. Расшифруй и распакуй (пароль — из `ПАРОЛЬ-БЭКАПОВ.txt`):

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in infinity-db.sqlite.gz.enc -out infinity-db.sqlite.gz -pass stdin
```

```bash
gzip -d infinity-db.sqlite.gz
```

Пароль вводится после запуска первой команды (через `stdin`, чтобы не остался в истории).

3. Проверь файл:

```bash
sqlite3 infinity-db.sqlite "PRAGMA integrity_check; select count(*) from users;"
```

Ожидание: `ok` и число пользователей.

4. На новом сервере: код из GitHub, файл положить как `/opt/tg-music-bot/music_bot.db`,
   затем `alembic upgrade head` (догонит схему, если бэкап старше кода) и запуск сервисов.

## Восстановить на том же сервере (сломалась база, сервер жив)

Остановить всё, что пишет в базу, подменить файл снимком, запустить:

```bash
systemctl stop tg-music-bot tg-music-api tg-music-worker tg-music-youtube-user
```

```bash
cd /opt/tg-music-bot && cp music_bot.db /root/music_bot.db.broken && cp backups/db-ГГГГММДД-ЧЧММСС.sqlite music_bot.db && rm -f music_bot.db-wal music_bot.db-shm
```

```bash
systemctl start tg-music-bot tg-music-api tg-music-worker tg-music-youtube-user
```

## Проверка, что бэкап годный (делалась 16.09)

Снимок копируется во временный файл, дальше `PRAGMA integrity_check`, сверка
миграции с продом, запуск приложения поверх копии, копия удаляется. Результат
16.09: целостность ok, схема = прод, 69 пользователей и 7589 треков читаются.
Повторять раз в месяц — бэкап, который ни разу не восстанавливали, это надежда, а
не бэкап.
