# Блок C — Парсеры (цели владельца, 2026-07-25)

Два независимых парсера:

## Парсер #1 — Массовая закачка SoundCloud 24/7 (автономный)

**Цель (задана владельцем):**
- **1 000 000 треков** — от самых популярных к андеграунду
- **10 000 артистов**
- Источник — **только SoundCloud** (никаких VK/Яндекс здесь)
- Полностью **без участия владельца**: сам находит профили артистов и ссылки на SoundCloud в интернете, сам ставит в очередь и качает **треки + альбомы (sets) + плейлисты** 24/7

**Что уже есть и переиспользуется:**
- `artist_research.py` + MusicBrainz (`musicbrainz.py`) + Deezer — находят артистов и их SC-ссылки
- `attach-sources` (CLI research) — привязывает SoundCloud приоритетнее YouTube
- `soundcloud.py` — качает `/tracks`, `/sets`, `/albums`, `/likes`, поиск `scsearch`
- `soundcloud_sources` + ежедневный таймер `youtube scan-due` — очередь и инкрементальный скан
- `soundcloud_imported` — дедуп уже скачанных ссылок

**Статус (2026-07-25):** массовый парсер переведён на **SoundCloud-only** —
`attach_source_for_artist` больше не заводит YouTube-источники ([artist_research.py](../../app/services/artist_research.py)),
нет SC → `no_source`. Чистка прошлых research-YouTube: `python -m app.cli.research disable-youtube-sources`
(отключает только автозаведённые, каналы владельца не трогает).

**Что достроить:**
1. **Автодискавери артистов до 10k** без списка от владельца: посев из чартов/популярного + обход «похожих артистов» (MusicBrainz relations / Deezer related / SoundCloud related), пока не наберётся 10 000 с привязанным SC-источником. Приоритет — по популярности (сверху вниз).
2. **Скачивать не только треки, но альбомы и плейлисты** профиля (sets/albums уже поддержаны загрузчиком — убедиться, что скан профиля их обходит).
3. **Счётчик прогресса к цели** (сколько треков/артистов из 1M/10k) — видно в админке.
4. Темп под 1M: concurrency SC-воркера, прокси-ротация (уже есть), паузы анти-бан. При текущих ~3000/сутки 1M ≈ год — заложить масштабирование (несколько воркеров/прокси).

## Парсер #2 — Поисковый (по запросу пользователя)

- Юзер пишет название **как угодно**: транслит, кириллица, опечатки, любой язык («Kizaru фейк айди», «Элджей розовое вино») → находит трек и похожие
- Порядок источников: **YouTube Music → SoundCloud → VK/Яндекс**
- Только **mp3** (приоритет), затем остальные форматы
- **Спрятан**: нигде в интерфейсе не показывается, не упоминается в текстах, не палится факт существования
- В конце блока C — **проверить поисковый парсер вживую**

**Статус (2026-07-25):** ядро поискового парсера готово — [search_download.py](../../app/services/search_download.py)
(`search_and_download`: SoundCloud → YouTube через yt-dlp, приоритет mp3;
`fetch_track_by_query`: минт в базу + библиотеку). Celery-задача `search.fetch`
([tasks/search_fetch.py](../../app/tasks/search_fetch.py), очередь `youtube_user`).
Живой прогон: `python -m app.cli.search_fetch "запрос" [--user tid]`. Осталось:
спрятанная привязка к промаху поиска в Mini App (авто-дозагрузка) + VK/Яндекс.

## Общие требования блока C
- Чистка названий от мусора: «премьера/клип/official video/лирик» — но «(Remix)», «prod.» и т.п. сохранять (это часть названия трека). Ошибочные видео-скачивания (клипы) метить/чистить.
- Только mp3 в выдаче (перекодирование при необходимости), приоритет mp3 везде.
