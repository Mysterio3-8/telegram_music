# SPEC 2.0 — Обновление TG Music Mini App

Источник: требования владельца от 2026-07-25 (33 раздела, две части).
Решения владельца зафиксированы в разделе «Ответы на вопросы».
Дополняет [SPEC.md](docs/архив/SPEC.md) и [SPEC-КАТАЛОГ.md](docs/архив/SPEC-КАТАЛОГ.md), не заменяет их.

---

## Цель

Довести TG Music до состояния «настоящее мобильное приложение»: чистый быстрый
интерфейс без багов, каталог на миллион треков, наполняемый автономно 24/7,
и работающая машина роста (рефералка, достижения, конкурсы, аккаунты артистов).

## Ответы на вопросы (решения владельца)

| Вопрос | Решение |
|---|---|
| БД под 1M треков | **PostgreSQL сейчас** (+ pg_trgm для поиска). Аудио на диск не ложится — байты живут в Telegram по `tg_file_id` |
| Порядок работ | **UI/UX + баги + скорость** первым срезом, дальше по списку срезов ниже |
| Графика | Владелец генерирует иконки по **промтам от разработчика** ([docs/ICON-PROMPTS.md](docs/архив/ICON-PROMPTS.md)). До получения файлов — рабочий SVG-фолбэк, чтобы работа не блокировалась |
| Новые подсистемы | **Все**: караоке+автомодерация, аккаунт артиста, друзья, конкурсы, итоги года |
| Срочное | **Конкурс с итогами 9 августа** — баннер в Mini App, кнопка «Участвовать», рассылка в боте. Делается первым, вне очереди |

---

## Стек (без изменений, кроме БД)

- Python 3.12, aiogram 3, FastAPI, SQLAlchemy 2 async, Alembic, Celery + Redis
- **PostgreSQL** (переезд с SQLite) + `pg_trgm` для нечёткого поиска
- Mini App: ванильный JS (ES-модули), без фреймворка — не меняем
- Хранение аудио: Telegram `tg_file_id` (основное) + LRU-кэш на диске
- Деплой: VPS keybest.cc, systemd + nginx

## Инварианты этого обновления

Дополняют инварианты в [CLAUDE.md](CLAUDE.md), нарушать нельзя:

1. **Формулировки** (§12, §29). В коде, UI, документах, ответах бота запрещены слова:
   `парсинг`, `парсер`, `скачивание`, `скачать музыку`.
   Разрешено: `добавление трека`, `загрузка трека`, `импорт трека`,
   `перенос музыки`, `перенос из других сервисов`.
   Внутренние имена модулей (`downloader.py`) не переименовываем — они не видны
   пользователю; запрет касается **всего, что видит пользователь**.
2. **Мини-плеер не исчезает** ни на одном экране и переживает перезапуск Mini App
   (позиция и трек восстанавливаются).
3. **Никаких накруток**: любое событие, дающее награду (прослушивание, реферал,
   достижение), проходит серверную проверку и дедуп. Клиент не является источником
   правды по статистике.
4. **Нет бесконечных загрузок**: каждый экран имеет три явных состояния —
   загрузка / данные / пусто-или-ошибка с кнопкой «Повторить».
5. Ответственность за контент — на пользователях (§30), тексты документов обязаны
   это отражать.
6. **Две ветки пополнения каталога независимы и не смешиваются** (решение владельца):
   - **массовая, 24/7, автономная — только SoundCloud.** Ежедневный таймер трогает
     исключительно SoundCloud-источники; YouTube-источники остаются, но сканируются
     только вручную;
   - **поиск по запросу пользователя — ищет во всех источниках сразу** и выбирает
     лучшее совпадение. Скрытая ветка: в интерфейсе не упоминается.

## Срезы

Каждый срез — рабочая функция end-to-end, с тестами, доводится до зелёного перед
следующим. Порядок — сверху вниз.

### Срез −1 — Две ветки пополнения каталога ✅ сделано

- Массовая закачка 24/7 переведена только на SoundCloud: ежедневный таймер
  (`youtube scan-due`) больше не трогает YouTube-источники.
- Поиск трека по свободному запросу во всех источниках:
  [track_lookup/](app/services/track_lookup/) — транслит, кириллица, опечатки,
  отсев клипов и промо, устойчивость к отказу отдельного источника.
- Загрузка найденного из его источника; YouTube приводится к mp3.

### Срез 0 — Конкурс (дедлайн 9 августа) ✅ сделано

- Модель `contests` + `contest_participants` (миграция `a367a749c438`).
- Условия проверяются сервером: подписка на канал (getChatMember) и приглашённые друзья.
- API: `GET /contests`, `POST /contests/{id}/join`.
- Mini App: баннер на главной + экран конкурса с условиями и кнопкой «Участвовать».
- Бот: кнопка «Участвовать» под постом рассылки, обработчик с перепроверкой условий.
- CLI: `create` / `list` / `announce` (рассылка поста с кнопкой) / `draw` (розыгрыш).
- Победитель — `secrets.choice` среди прошедших перепроверку условий на момент
  розыгрыша; Premium начисляется автоматически, победителю уходит сообщение.

**Что конкурс проверить не может:** репост во ВКонтакте и в Telegram Stories —
у Telegram нет API, чтобы это увидеть. Эти условия остаются на честном слове;
сервером гарантированы только подписка на канал и приглашённые друзья.

### Срез 1 — UI/UX, баги, скорость (§1, §2, §3, §22, §25)

- Единая система: токены, размеры кнопок по скринам, свой SVG-иконсет, фоны.
- Нижняя панель закреплена, ничего не просвечивает; мини-плеер всегда виден.
- Навигация «назад» по стеку экранов (плеер → настройки плеера → назад в плеер).
- Жесты: свайп вправо — назад, свайп между треками, плавные анимации.
- Производительность: убрать сброс скролла и лишние перерисовки, кэш ответов,
  скелетоны вместо бесконечных спиннеров.
- Фикс: фото профиля не помещается в блок (§22).

### Срез 2 — PostgreSQL + поиск (инфраструктура под каталог)

- Переезд БД, перенос данных, индексы, `pg_trgm` для поиска с опечатками.
- Поиск по транслиту и кириллице, устойчивый к опечаткам.

### Срез 3 — Автопополнение каталога 24/7 (§4, §31, §32, §33)

- Автодискавери артистов до 10 000 (чарты → похожие артисты), треки до 1 000 000.
- Источники: SoundCloud → YouTube Music → YouTube.
- Обложки обязательны, метаданные полные, жанры и поджанры.
- Фильтрация: клипы, видео, мусор не попадают в базу (§11).
- Счётчик прогресса к цели в админке; по достижении цели — режим ожидания (§33).
- Карточки артистов создаются автоматически (§31).

### Срез 4 — Импорт по ссылке и перенос (§10, §26, §27)

- Импорт только по ссылке: поиск трека → SoundCloud → YouTube Music → YouTube.
- Обложка, название, исполнитель, метаданные — обязательны.
- Ручная загрузка: выбор жанра и поджанра, заполнение метаданных (§26).
- Починить перенос из сервисов — ошибка «сервис не распознан» (§27).

### Срез 5 — Рекомендации, топ, минусы (§7, §8, §20, §21)

- TG Mix на реальных сигналах: жанры, поджанры, история, лайки, похожие артисты.
- Рейтинг: прослушивания + лайки + популярность + личная история.
- Минусы: отдельный поиск, отдельный рейтинг, обложки, исправленный импорт.

### Срез 6 — Плеер, офлайн, эквалайзер, караоке (§5, §6, §9)

- Настоящее офлайн-прослушивание с сохранением треков.
- Профессиональный эквалайзер.
- Караоке-режим; кнопка «Загрузить текст» с автомодерацией без админа (§6).

### Срез 7 — Рост и монетизация (§13—§18, §23, §24, §28)

- Premium: больше преимуществ, ненавязчивые баннеры, скидки на длинные подписки,
  «навсегда» убрано из продажи (только по рефералке), подпись платёжного сервиса убрана.
- Рефералка: 14 порогов от 1 друга до 10 000 друзей, честная проверка.
- ~200 достижений с наградами: Premium, эмодзи, рамки, значки, титулы, аватарки,
  стикеры, оформление профиля.
- Акции, конкурсы, итоги года, друзья с приватностью.
- Аккаунт артиста: подтверждение владения, публикация треков, подписка ×2-3 от Premium.
- Честная статистика без накруток (§17).

### Срез 8 — Документы (§12, §19, §29, §30)

- FAQ расширенный и информативный.
- Во всех документах: ответственность пользователей, открытые источники,
  порядок обращения правообладателя, концепция свободного доступа.
- Вычистить запрещённые формулировки везде.

## Риски

| Риск | Что делаем |
|---|---|
| 1M треков при текущем темпе ≈ год | Масштабирование: воркеры + прокси, приоритет по популярности сверху вниз |
| Переезд на PostgreSQL — простой прода | Переносим ночью, старую SQLite оставляем копией для отката |
| ~200 достижений — легко сделать формально «для галочки» | Достижения генерируются из категорий с реальными порогами, каждое проверяемо запросом |
| Автомодерация текстов пропустит мусор | Сверка с источником + эвристики; при неуверенности — отклонять, а не публиковать |
| Конкурс: накрутка участий | Проверка условий на сервере, один участник = один Telegram-аккаунт |
