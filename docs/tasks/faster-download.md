# Ускорить загрузку трека

**Статус:** ⚪ не начато
**Из чек-листа:** [CHECKLIST.md](../../CHECKLIST.md) → «Дальше по плану»

## Где мы сейчас

| Этап | Время |
|---|---|
| Поиск | 0.22 сек |
| Скачивание + перекодирование | 7-14 сек |

Поиск оптимизирован до предела (прямой API поверх keep-alive соединения).
Всё оставшееся время — загрузка.

## Куда смотреть

1. **Пропускать ffmpeg, когда источник уже отдаёт mp3.** Сейчас `as_mp3=True`
   гонит перекодирование всегда. SoundCloud для многих треков отдаёт
   progressive-поток уже в mp3 — там конвертация лишняя. Это и время, и память
   (ffmpeg дважды ронял прод по OOM).
2. **yt-dlp поднимает новое соединение на каждую загрузку** — та же болезнь, что
   была у поиска. Проверить, переиспользуется ли соединение внутри одной задачи.
3. **Отдавать трек потоком, не дожидаясь полной загрузки.** В Mini App уже так
   (`/stream/{ref}` с Range). В боте нельзя — Telegram требует файл целиком.

## Чего не ждать

Ниже нескольких секунд на первый показ трека не опуститься: файл надо получить с
источника. «Мгновенно» даёт только предварительный минт — см.
[warmup-catalog.md](warmup-catalog.md).
