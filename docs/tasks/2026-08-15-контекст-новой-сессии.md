## Что за проект и куда идём

Telegram-бот: человек пишет название → получает трек аудиосообщением за секунды.
Источники опрашиваются вживую (SoundCloud основной, YouTube фолбэк), каталог
специально не копим. Плюс Mini App-плеер на keybest.cc и Premium 29 ₽/мес.

Цель владельца: любой трек за 1–3 секунды, красивая выдача, окупаемость.
Владелец учится программировать и хочет сам вносить правки.

**Приоритеты его словами:** «красиво, быстро, оригинал» —
см. `docs/tasks/2026-08-14-приоритеты.md`.

## Доступ и рабочий цикл

- SSH работает и из PowerShell (`ssh news-rewriter-vps`), и из Bash.
  ✅ **Правка 16.08:** прошлый вывод «только через PowerShell» неверен. Ломался не
  инструмент, а раскрытие `~`: домашний каталог `C:\Users\Илья` кириллический, и
  Git Bash отдаёт ssh путь в другой кодировке — `no such identity:
  /c/Users/\310\353\374\377/.ssh/id_ed25519`. Лечится windows-путями:
  `ssh -i "C:/Users/Илья/.ssh/id_ed25519" -o UserKnownHostsFile="C:/Users/Илья/.ssh/known_hosts" root@38.244.213.132`.
  Знать это важно: классификатор разрешений на PowerShell отваливается, и тогда
  Bash — единственный путь к серверу.
- ⚠️ В PowerShell 5.1 кавычки внутри аргументов до `ssh` не доходят — нужен
  стоп-токен: `ssh --% news-rewriter-vps "команда 'с кавычками'"`.
- Деплой: `cd /opt/tg-music-bot && bash deploy/update.sh`.
- ⚠️ **Оборванный деплой не откатывается.** 14.08 SSH сбросило посреди
  `update.sh`: код и миграции доехали, а перезапуск сервисов — нет, и бот 20
  минут работал на старом коде. Проверять:
  `systemctl show tg-music-bot -p ActiveEnterTimestamp` против времени файлов.

### 🔴 Главное ограничение работы: бокс одноядерный

961 МБ, **одно** ядро. **Массовые тесты СКАЧИВАНИЯ роняют sshd** — за 14–15.08
это случилось трижды. Сервер при этом жив и отвечает по HTTPS; надо просто
подождать несколько минут.

**Тесты поиска безопасны** (0.2 сек, без ffmpeg) — их можно гонять свободно, и
именно так найдены все баги ранжирования. Тесты скачивания — только поштучно.

## Решения владельца (не переспрашивать)

- **DRM не обходим.** Отказано четырежды, включая присланный «код от Warner Music
  Group» с pywidevine (он к тому же нерабочий — не импортирует base64/pywidevine,
  ffmpeg `-decryption_key` не принимает MPD по URL).
- **Возрастные ограничения YouTube не обходим** — это защитный механизм.
  Легальный путь один: куки взрослого аккаунта, `YOUTUBE_COOKIES_PATH`.
- **Оплата:** Stars + ЮKassa рядом. **Массовый парсер выключен насовсем.**
- **Скачивание по прямой ссылке SoundCloud — только Premium** (с 14.08 подписка
  нужна на ЛЮБУЮ ссылку; загрузка своим файлом бесплатна и без лимитов).
- **Алерты сторожа — второму админу** (`HEALTH_ALERT_CHAT=7446911479`).
- Кнопка «Редактировать (админ)» из карточки трека убрана.

## Что сделано 13–15.08

**Спека 13.08 закрыта целиком** (`docs/tasks/2026-08-13-СПЕКА-качество-и-деньги.md`):
лучшее качество + `/settings`, Stars рядом с ЮKassa, обложка отдельным файлом,

**YouTube починен.** С IP сервера блокируется на всех 10 player-клиентов.
Работает единственная связка: **прокси + `player_client=tv_embedded`**; порознь
ни то ни другое не помогает. Xray на сервере, 5 socks-входов 10811–10815,
`YOUTUBE_PROXY` — список через запятую, перебор со сдвигом.
⚠️ Ротация дала 1 из 6 против 3 из 4 на одном выходе — выходы неравноценны,
`YOUTUBE_PROXY_ATTEMPTS=2`. Довести не удалось: нужны массовые скачивания.

**Поиск — четыре бага, все найдены замером на 25 живых запросах:**
1. `rank_candidates` **не применялся к списку в боте** — выдача уходила в
   сыром порядке SoundCloud;
2. `official` был старшим ключом сортировки, а ставит его сам заливщик:
   пародия с 41 прослушиванием стояла первой;
3. `artist_hit` требовал, чтобы ВЕСЬ запрос был подстрокой имени артиста —
   молчал на «макан назови её». Добавлен `artist_affinity` (max двух покрытий,
   фонетика, правило `c → k`: «макан» ↔ «MACAN»);
4. локальный поиск сортировался `ORDER BY artist, title` — по алфавиту.
   Добавлен `app/services/track_ranking.py`, пул 200 строк, ранжирование в Python.

Плюс: починка битой кодировки (`app/services/mojibake.py`), разбор исполнителя у
YouTube-кандидатов, доспрос по имени артиста, если его нет в выдаче.

🔴 **Сброс кэша в `update.sh` не работал** для многословных запросов — `xargs`
без `-d '\n'` резал ключи по пробелам. Это и была загадка «деплой не дошёл»,

**Загрузка по ссылке с любой площадки** (`app/services/link_import.py`) — yt-dlp

## 🔴 Авария 15.08 и текущая работа

**В Mini App не играл ни один трек** — бесконечное «не удалось запустить трек,
пропускаю».

Причина: `file_id` принадлежит боту, который загрузил файл. После переезда на
`@muz_damn_bot` (05.08) идентификаторы старого каталога стали чужими. В боте
самолечение было, **в API — нет**, он отдавал 404, плеер шёл к следующему треку
с таким же мёртвым id.

Замер: **7223 трека из 7491 (96%) мертвы**, живых 262, архивных копий **ноль**.

Сделано:
- API гасит мёртвый id и ставит `repair_track` (`app/api/routers/audio.py`);
- плеер: потолок 4 промаха вместо длины очереди, текст «восстанавливаем эти
  треки — попробуйте через минуту» (`miniapp/src/state.js`);
- `app/cli/repair_catalog.py` — пакетный ремонт, живость проверяется дешёвым
  `get_file`. **Поставлен в ночное обслуживание: 100 треков/ночь, `--popular`.**
  Проверено вживую: 7 из 8 восстановлены.

**Каталог оживает ~10 недель.** Это и есть фоновая работа, идущая сейчас.

   песню. Попутно найден настоящий дефект — добор по имени артиста раздувал
